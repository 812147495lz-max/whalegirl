# WhaleGirl for macOS —— DeepSeek 鲸鱼娘桌宠总体开发方案

> **方案版本**：V1.1（跨 DPI 显示与角色尺寸修订）  
> **整理日期**：2026-10-10  
> **实施平台**：macOS / Apple Silicon（首先落地）；**尺寸兼容基准**：MacBook Air M4 13/15 英寸、Windows 4K 3840×2160（150%/200% DPI，Windows 客户端属后续移植）  
> **项目定位**：菜单栏常驻 + 偶发半身探头 + 桌面自主游荡 + Codex / DeepSeek Harness 统一事件通知 + 系统监控  
> **预算约束**：桌宠自身新增的模型 API 费用不超过 **¥2/天**（不包括 Codex / DSH 正常开发任务的费用）  
> **实施原则**：单个原生 macOS 应用；优先复用开源能力；低 CPU / 低内存 / 低打扰；不擅自修改文件。

---

## 0. 执行摘要：最终决策

开发一个暂名 **WhaleGirl** 的 Swift/AppKit/SwiftUI 原生 macOS 应用。平时它是菜单栏里一只很小的 DeepSeek 鲸鱼娘，随机做表情、感知编程助手状态；鼠标靠近时从菜单栏探出半个身子，点击后以较大的姿态互动；电脑闲置时才偶尔跳到桌面上散步、追逐鼠标、围观、踢打、假装吃掉文件或图标。所有文件互动默认是**纯视觉表演**，不移动、不删除、不重命名文件。

**建议代码底座：**以 [AgentPet](https://github.com/ntd4996/agentpet) 的原生 macOS、多 Agent 和通知能力为主体；参考或移植 [RunRat](https://github.com/Lolretrorat/runrat) 的菜单栏动画与系统监控；借用 [DSH Pet](https://github.com/sundusk/dsh-pet) 的 DeepSeek Harness 事件桥接；优先研究 [whale-girl](https://github.com/vlln/whale-girl) 的鲸鱼娘角色图集和行为状态；借鉴 [Aibo](https://github.com/omdsh-dev/dsh-gal) 的闲置动作，[QiuQiu](https://github.com/jc98629/my-cat-desktop-pet) 的双 Agent 任务聚合、[OpenPets](https://github.com/alterhq/openpets) 的外部控制接口。

**不是同时运行以上项目**，而是将许可允许、技术可兼容的必要实现整合到 **WhaleGirl.app**，外加最少量的 DSH / Codex 事件适配器。哪些代码可以直接复制、哪些需要重写，须以实际源码、依赖、许可证审核结果为准。

**最小可用版本（MVP）优先实现：**菜单栏鲸鱼头像、基础动画、鼠标悬停探头、点击显示系统面板、Codex/DSH 双通知、事件去重、基本设置。邮箱和高阶桌面游荡在随后阶段实施。

## 1. 用户需求与产品边界

### 1.1 必须实现的体验

1. **日常存在感极低**：菜单栏小鲸鱼娘待机、眨眼、打哈欠、根据状态变化表情，不占据桌面大片空间。
2. **偶尔“探出半个身子”**：从菜单栏下沿扒出来，鼠标悬停时抬头看鼠标，收到通知时举牌、挥手或抱信封。
3. **大姿态鼠标互动**：主动点击后可从菜单栏弹出，展示基于当前屏幕可用高度自动缩放的大型半身角色（默认约占可用屏高的 22%）；摸头、戳脸、躲避、追逐、拖动、抗议等动作。
4. **空闲时自主活动**：长时间没有人操作电脑时从菜单栏跳下，桌面散步，坐在 Dock 附近，与鼠标/桌面图标做视觉互动，最终回到菜单栏。
5. **统一编程助手通知**：同时接收 DeepSeek Harness（DSH）与 Codex 的运行、等待输入/审批、完成、异常和会话状态；多个并行会话互不覆盖。
6. **邮件提醒**：显示新邮件数量和重要邮件提醒，点击跳往邮件应用；不要求桌宠读取或上传所有邮件正文。
7. **RunCat 式系统面板**：CPU、内存、网络、磁盘、电池等状态，附打开“活动监视器”的快捷操作。
8. **性格和吐槽**：优先基于本地规则和台词库；根据应用、系统状态、编程任务事件偶尔生成轻松、毒舌或抽象台词。
9. **低资源、低成本**：驻留应尽可能不影响电池续航；不持续运行本地大模型；不持续截图；模型费用每日硬上限 ¥2。

### 1.2 可选扩展

- Codex 额度消耗监测、额度快用完提示转 DSH、恢复后提示切回；跨 Agent 自动续接仅作为后续研究功能。
- Windows / ComfyUI 视频生成、远程机器任务完成通知。
- 每日任务摘要、通知历史、错误归因简述、角色成长和成就。
- 个性化语音、跨屏幕游荡、复杂小剧场、可换装角色包。

### 1.3 明确不做或不默认开启

- 不自动删除、移动、重命名、覆盖桌面文件；“吃掉图标”仅视觉特效。
- 不自动批准 Codex/DSH 的高风险操作；第一版只提示并跳转到原应用。
- 不录制键盘输入、不默认读取聊天或邮件正文、不持续上传屏幕。
- 不把 AI 模型接到逐帧动画控制循环里。
- 不强依赖联网才可以播放动画或接收本地任务状态。

### 2.3 选择 AgentPet 而不是 RunRat 做主干的理由

AgentPet 更接近一个“多 Agent 事件驱动的桌宠”，已有相对完整的通知与会话管理方向；RunRat 则接近单用途系统指标菜单栏程序。从后期维护看，通知去重、任务恢复、多个 Agent 并发比绘制状态栏图标更容易出逻辑 bug，因此优先保留 AgentPet 的基础架构，再引入 RunRat 的指标/UI。

**备选路线**：如果 AgentPet 的许可证、依赖、窗口模型或架构过重，改为以 RunRat 为超轻量壳体，重写 Event Hub 与 Overlay，并参照 AgentPet/QiuQiu 的逻辑。应在阶段 0 完成两种路线的短 PoC 对比后锁定，避免重构中途频繁换底座。

## 3. 鲸鱼娘美术资源和动作设计

### 3.1 素材来源

**首选参考来源：**`vlln/whale-girl`。优先保留现有 DeepSeek 鲸鱼娘的辨识度、色彩、服装与表情体系；把既有图集用作原型动作。Aibo 的动画用来参考动作时序和闲置调度，而不是混用两套不统一画风的角色图片。

**许可前置条件**：仓库代码许可证与美术原作授权可能不同。公开发布、重新打包发行和商用前必须分别确认代码、字体、原角色形象、每张图集/生成素材的许可来源；不明确的素材改为原创重绘或取得授权。记录每个素材的来源、作者、授权与版本。

### 3.2 三套尺寸与跨分辨率、跨 DPI 缩放规范（V1.2 按截图比例修订）

**核心原则：不要先拍脑袋写绝对像素，而是先确定“在屏幕里看起来占多大比例”。** 本节以用户提供的实际界面截图为视觉基准，按三个标注框的相对尺寸反推角色显示比例，再转换为 MacBook Air 与 Windows 4K 的默认尺寸。

#### A. 以用户截图反推的目标占比

用户截图尺寸约为 **2048 × 1884**。按标注框外接矩形估算：

- **小红框（Mini / Menu Bar）**：约 **57 × 48 px**，约占整屏 **宽 2.8% / 高 2.5%**。
- **中红框（Peek / 探身）**：约 **138 × 154 px**，约占整屏 **宽 6.7% / 高 8.2%**。
- **大黄框（Full / 游荡与互动）**：约 **230 × 283 px**，约占整屏 **宽 11.2% / 高 15.0%**。

这三个数值不是“素材原始分辨率”，而是**角色在屏幕上看起来应占的面积级别**。后续所有屏幕适配都应优先保持这种观感比例。

#### B. 三种形态的比例目标

| 形态 | 目标观感比例 | 解释 |
|---|---|---|
| **Mini / Menu Bar** | 约 **屏高的 2.5%** | 对应菜单栏里的极小头像；重点是“看得清”，不是严格跟比例放大缩小 |
| **Peek / Half-body** | 约 **屏高的 8%–9%** | 对应从菜单栏探出半身、举牌、挥手、偷看鼠标 |
| **Full / Desktop** | 约 **屏高的 15%–16%** | 对应空闲游荡、鼠标互动、踢图标、抱文件、假装啃文件 |

推荐写入代码的默认值：

- `peekHeight = screenHeight × 0.082`
- `fullHeight = screenHeight × 0.150`
- `activeHeight = screenHeight × 0.165 ~ 0.180`（当用户主动互动时，可在 Full 基础上再放大 10%–20%）

其中 `screenHeight` 指**角色当前所在显示器的总逻辑高度**；而不是某个固定的像素高度。Mini 因为受菜单栏 / 托盘容器限制，单独处理。

#### C. 换算到目标设备上的默认显示尺寸

##### 1. MacBook Air M4 13.6 英寸

设计参考逻辑高度：约 **956 pt**（实际应以 `NSScreen.frame.height` / `visibleFrame` 实测）。

| 形态 | 按比例换算的默认高度 | 说明 |
|---|---|---|
| **Mini / Menu Bar** | 理论值约 **24 pt** | 受菜单栏限制，建议实际显示 **20–24 pt**；使用专用小头像，不直接缩全身图 |
| **Peek / Half-body** | 约 **78 pt** | 探头、挥手、举牌、偷看鼠标；2× Retina 渲染约 156 px |
| **Full / Desktop** | 约 **143 pt** | 桌面游荡、踢图标、抱文件；2× Retina 渲染约 286 px |
| **Full / Active** | 约 **158–172 pt** | 主动鼠标互动时临时放大；2× Retina 渲染约 316–344 px |

##### 2. MacBook Air M4 15.3 英寸

设计参考逻辑高度：约 **1107 pt**。

| 形态 | 按比例换算的默认高度 | 说明 |
|---|---|---|
| **Mini / Menu Bar** | 理论值约 **28 pt** | 仍受菜单栏限制，建议实际显示 **20–24 pt**；不要随屏幕无上限增大 |
| **Peek / Half-body** | 约 **91 pt** | 2× Retina 渲染约 182 px |
| **Full / Desktop** | 约 **166 pt** | 2× Retina 渲染约 332 px |
| **Full / Active** | 约 **183–199 pt** | 2× Retina 渲染约 366–398 px |

##### 3. Windows 4K（3840 × 2160）150% 缩放

设计参考逻辑高度：**1440 DIP**。

| 形态 | 按比例换算的默认高度 | 对应物理像素（约） |
|---|---|---|
| **Mini / Tray** | 理论值约 **36 DIP** | 约 **54 px**；实际需服从系统托盘高度，可落在 **24–32 DIP** |
| **Peek / Half-body** | 约 **118 DIP** | 约 **177 px** |
| **Full / Desktop** | 约 **216 DIP** | 约 **324 px** |
| **Full / Active** | 约 **238–259 DIP** | 约 **357–389 px** |

##### 4. Windows 4K（3840 × 2160）200% 缩放

设计参考逻辑高度：**1080 DIP**。

| 形态 | 按比例换算的默认高度 | 对应物理像素（约） |
|---|---|---|
| **Mini / Tray** | 理论值约 **27 DIP** | 约 **54 px**；实际仍应服从托盘高度 |
| **Peek / Half-body** | 约 **89 DIP** | 约 **178 px** |
| **Full / Desktop** | 约 **162 DIP** | 约 **324 px** |
| **Full / Active** | 约 **178–194 DIP** | 约 **356–388 px** |

可以看到，**同一块 4K 屏在 150% 和 200% 缩放下，物理像素观感会接近，而逻辑尺寸不同**。这正是采用“按屏幕比例 + DPI 感知”的原因。

#### D. 为什么 Mini 不能机械按比例无限放大

虽然小红框按截图比例推算在大屏上可能达到 27–36 DIP，但菜单栏 / 托盘图标本身受系统容器限制：

- macOS 菜单栏通常只能容纳约 **20–24 pt** 级别的清晰图标。
- Windows 托盘也受任务栏高度影响，不适合随屏幕尺寸无限增大。

因此 **Mini 的正确策略** 是：

1. 先服从系统容器高度；
2. 采用**专门的小头像 / 上半身图集**；
3. 用少量大像素表情、清晰轮廓和高对比配色保证辨识度；
4. 不把 Full 或 Peek 的全身图机械缩小到菜单栏里。

换句话说：**Mini 要保证“不变形、看得清”；Peek / Full 才主要按比例缩放。**

#### E. 最终推荐的实现公式

- `screenHeight = 当前显示器总逻辑高度`
- `menuBarSpriteHeight = clamp(systemContainerHeight - padding, minMini, maxMini)`
- `peekHeight = round(screenHeight × 0.082 × userScale)`
- `fullHeight = round(screenHeight × 0.150 × userScale)`
- `activeHeight = round(fullHeight × activeScale)`，其中 `activeScale` 默认 `1.10 ~ 1.20`

推荐参数：

- `userScale`：默认 `1.0`，设置中允许 **0.8–1.3**。
- `minMini / maxMini`：macOS 推荐 `20–24 pt`，Windows 推荐 `20–32 DIP`。
- `activeScale`：默认 `1.15`。
- 当 `fullHeight` 超过工作区高度的 **22%** 或交互区域遮挡明显时，允许自动缩回到 `0.90×`。

#### F. 宽度、碰撞箱与锚点

宽度不要单独写死为某个百分比，而应由素材纵横比自动得出。一般可预期：

- Mini 宽度大致接近 **屏宽的 2.5%–3.5%**。
- Peek 宽度大致接近 **屏宽的 6%–8%**。
- Full 宽度大致接近 **屏宽的 10%–13%**。

但代码层面应以：

- **视觉包围盒（visual bounds）**
- **碰撞箱（collision bounds）**
- **足底锚点（foot anchor）**
- **菜单栏锚点（menubar anchor）**

来驱动角色站位和互动，而不是只靠一整个矩形框。

#### G. 素材要求（按这套比例反推）

| 形态 | 建议素材策略 |
|---|---|
| **Mini / Menu Bar** | 独立小头像 / 小上半身图集；必要时逐帧重绘，优先辨识度 |
| **Peek / Half-body** | 单帧有效角色高度建议不低于 **160–220 px**（逻辑显示），源图建议至少 **512 px** 高 |
| **Full / Desktop** | 单帧有效角色高度建议不低于 **280–380 px**（逻辑显示），源图建议至少 **768–1024 px** 高 |

如果继续沿用现成像素风素材，应验证在上述比例下是否糊掉。若发丝、脸和手势在 Mini / Peek 下不可辨识，需增加专用重绘版本。

#### H. 一句话结论

**按你这张图的目标观感，正确的尺寸逻辑不是“菜单栏 50 pt、探头 200 多 pt、桌面 500 多 pt”，而是：**

- **菜单栏小头像：约占整屏高 2.5%，但受系统容器限制，实际以 20–24 pt（Mac）/ 20–32 DIP（Win）为主；**
- **探头半身：约占整屏高 8%–9%；**
- **桌面游荡 / 鼠标互动：约占整屏高 15%–16%，主动互动时再扩大 10%–20%。**

这样做，既能保持你图中想要的屏幕占比，也能保证菜单栏的小红框不会因为硬缩放而变形、糊掉、看不清。

### 3.3 关键动作列表

**基础动作：**`idle`、`blink`、`sleep`、`think`、`work`、`happy`、`error`、`waiting_approval`、`walk`、`dragged`。

**新增菜单栏专属动作：**`peek_down`、`hang_from_menubar`、`wave`、`slide_out`、`climb_back`、`show_letter`、`point_notification`。

**新增桌面互动动作：**`jump_down`、`land`、`wander`、`inspect_icon`、`kick_icon`、`pretend_eat_icon`、`sit_on_dock`、`mouse_chase`、`mouse_avoid`、`trip`、`return_home`。

设计中每个动作至少定义：资源帧、播放帧率、循环策略、可否打断、进入/退出动画、碰撞轮廓、优先级、声音（可选）、资源回收时机。

### 3.4 动画优化

- 平时菜单栏约 4–8 FPS 的轻量动画足够，静止时可停止刷新。
- 完整动画按需加载，离开桌面形态后及时释放不再需要的纹理。
- 在低电量、系统“减少动态效果”、全屏/会议/专注模式下减少或暂停主动游荡。
- 图像缓存优先，避免每一帧重新从磁盘解码。
- 由本地状态机选动作，不通过 API 生成逐帧决策。

## 4. 三种展示形态与 macOS 窗口技术

### 4.1 状态 A：菜单栏常驻

- 使用 `NSStatusItem` / `NSStatusBar` 显示小鲸鱼头像。
- 常规是菜单栏**右侧状态区**；苹果菜单附近的左侧不属于第三方状态栏图标的正常插入区。
- 单击打开 Dashboard；鼠标悬停可延迟触发 Peek；右键菜单显示暂停、设置、静音、退出。
- 允许用户通过 macOS 适用的菜单栏重排方式管理位置，不承诺固定到最左侧。

### 4.2 状态 B：探出半身与大姿态交互

- 在菜单栏头像的屏幕坐标下方建立无边框透明 `NSPanel` 或合适的 `NSWindow`。
- 播放“菜单栏头像缩小/消失 → 半身从该处滑出”的连续动画。
- 大部分透明区域应点击穿透；角色有效命中区域才拦截鼠标。
- 不主动抢键盘焦点；点击后可选择打开面板或与人物互动，避免两个动作冲突。
- 角色有消息气泡时，气泡与角色使用相同锚点坐标计算位置。

**难点**：macOS 菜单栏状态项与应用绘制的透明窗本来就不是一套渲染层。所谓“从菜单栏跳出”属于视觉衔接动画，不是把真实系统图标拖出菜单栏。

### 4.3 状态 C：桌面游荡

- 当电脑空闲（默认可设 10 分钟）且非全屏会议等抑制情境时，根据概率触发。
- `jump_down → land → wander → inspect_icon / chase_mouse / sit / sleep → return_home`。
- 只在用户未明显操作时发生；用户回来时收敛到角落或自动回菜单栏。
- 允许碰到 Dock 或 Finder 图标时播放“踢一脚”“咬一下”“抱一下”等视觉动作。
- 角色的活动边界应按当前屏幕 `visibleFrame`、菜单栏、Dock 和安全区域计算，支持多屏和 Retina。

### 4.4 文件与图标交互的真实性边界

**V1：视觉假互动**——绘制角色动作和粒子特效，不动 Finder 图标与文件。可以通过桌面路径读取文件名/类型做轻量吐槽，但不能假设文件一定出现在屏幕某个坐标。

**V2：可见图标感知**——在得到授权时利用辅助功能（Accessibility）读取 Finder 桌面可见项目及其位置；成功则做更精准的“踢图标”动作，失败自动降级为在空白桌面游荡。不同 macOS 版本、桌面整理方式和多屏情况下，可见项目位置不一定可稳定获取。

**不实现真实删除/移动**。如果未来想做真实的临时图标替身，应先建立独立可撤销、隔离的视觉层，绝不能让桌宠后台操作真实文件。

### 4.5 应避免的窗口行为

- 抢焦点、遮挡用户输入区域、阻止鼠标正常点击或拖拽。
- 在视频会议、屏幕共享、全屏游戏中持续跳出。
- 在 Mission Control、Spaces 切换、睡眠/唤醒后残留不可点击的透明窗口。
- 截图或传输窗口内容作为“低成本”的常态识别方式。

## 5. 软件联动：接入方法与功能定义

| 软件/系统 | 首选接入方式 | 实际提供的功能 | 技术边界 |
|---|---|---|---|
| **Codex CLI** | AgentPet 既有 Hook / 官方可用通知配置 | 任务开始、完成、等待、失败；跳回会话；必要时展示额度 | 不可直接推断 CLI 支持等于 Codex App / IDE 都支持 |
| **Codex 桌面版/IDE** | 优先官方可用事件/API，必要时只读会话状态适配 | 与 CLI 聚合到同一列表 | 需对具体客户端版本逐一测试 |
| **DeepSeek Harness** | DSH Pet / Cordis 事件插件，通过本地 Socket 推送 | 状态、步骤、错误、等待回复/审批、完成 | 处理不同 Profile 与插件安装位置 |
| **邮件** | Apple Mail 集成或 IMAP IDLE/OAuth 只读连接 | 未读数、重要邮件、新邮件角标和跳转 | 不能假设所有邮箱开放 IMAP；不默认取全文 |
| **macOS 系统** | 原生进程与系统指标 API | CPU、内存、网络、磁盘、电池、前台应用 | 系统版本/沙盒权限影响部分指标 |
| **活动监视器** | `NSWorkspace` 打开系统 App | 一键打开活动监视器 | 不嵌入、也不伪称替代完整活动监视器 |
| **Finder 桌面** | 桌面目录元数据 + 按需辅助功能 | 围观、假踢、假吃图标，文件名相关吐槽 | “文件存在”与“屏幕可见位置”是不同信息 |
| **Dock** | 仅视觉区域推断，必要时尝试辅助功能 | 坐在 Dock 边缘，围观应用图标 | 不自动点击或拖拽 Dock 项 |
| **浏览器 / IDE** | 当前前台应用，按需读取窗口标题 | 本地规则吐槽、场景关联 | 默认不采集页面正文 |
| **Windows / ComfyUI** | 后期局域网 HTTP/WebSocket 发送结构化事件 | 视频生成完成、失败、队列耗时 | 独立配对认证、默认不对公网开放 |
| **DeepSeek API** | HTTPS，简短事件摘要 + 缓存 | 生成新的短台词、错误一句话摘要 | 有预算阈值、速率限制和隐私过滤 |

### 5.1 Codex + DSH 的核心原则

每个 **Agent + Session** 各自维护状态。不能因为 Codex 某个子任务完成就把整个鲸鱼娘状态重置为空闲；同时运行的 DSH 任务仍可能在工作。对于 Hook 漏报、进程退出、重复上报，要有去重和过期恢复。

用户希望的 **Codex 额度不足时切换 DSH**：第一版只做额度提醒、一键打开对应工具和跳往当前项目目录；第二版考虑“生成移交摘要 + 标记工作目录/未提交修改”的辅助交接；真正无缝跨工具继续同一会话属于独立、较难的集成项目。

### 5.2 邮件触发示例

- 普通新邮件：在面板计数，不主动跳出。
- 重要发件人/指定规则命中：鲸鱼娘抱信封探头，轻提示。
- 未读邮件积累：面板显示总数，触发一次后进入冷却，不重复骚扰。
- 内容提取：最小化，仅标题、发件人或元数据；需要正文摘要时须额外开启授权。

## 6. Event Hub：统一事件、队列与优先级

### 6.1 标准事件结构（建议）

```json
{
  "schemaVersion": 1,
  "eventId": "uuid-or-deterministic-id",
  "source": "codex",
  "sessionId": "session-123",
  "projectId": "AIShortFilm",
  "eventType": "approval_required",
  "state": "waiting_input",
  "title": "Codex 需要确认",
  "message": "有一步操作等待批准",
  "timestamp": "2026-10-10T14:00:00+08:00",
  "deepLink": null,
  "isSensitive": false
}
```

**`eventType` 建议枚举：** `session_started`、`working`、`tool_running`、`approval_required`、`waiting_input`、`turn_completed`、`session_completed`、`session_failed`、`quota_low`、`quota_recovered`、`mail_received`、`system_alert`。

每个适配器将不同来源的事件正规化；核心 App 不依赖某个工具的私有状态字段。

### 6.2 处理规则

1. 先按 `eventId` 或 `{source, sessionId, eventType, eventSequence}` 去重。
2. 单独维护每个会话最新状态、最后活动时间和待处理提醒。
3. 区分“某 Turn 完成”与“整个 Session 结束”，避免频繁庆祝。
4. 事件按优先级入队，多个低优先级事件合并为一条摘要。
5. 失联会话进入 `stale / uncertain`，不能简单判成失败。
6. 同类通知设置冷却窗口，提示过一次不再反复弹出。
7. 关键事件保留本地历史，支持点击回到原应用；跳转目标不存在则退化为打开相应 App。

### 6.3 优先级

| 优先级 | 事件 | 默认动作 |
|---|---|---|
| P0 | 请求用户批准、输入阻塞 | 立即停止游荡、探头并提示；不自动同意 |
| P1 | 任务失败、重要安全/系统异常 | 表情变化 + 一次通知 |
| P2 | 任务完成、重要新邮件 | 轻量动画 + 提示 |
| P3 | 任务运行中、普通邮件 | 菜单栏更新，不强制打扰 |
| P4 | 随机互动、闲置小剧场 | 仅在无高优先级任务时执行 |

## 7. Behavior Brain：无需持续消耗 Token 的行为引擎

### 7.1 状态机草案

```text
MenuBarIdle
  ├─ hover → Peek → MenuBarIdle
  ├─ click → InteractiveOverlay → MenuBarIdle
  ├─ high-priority event → AlertOverlay → MenuBarIdle
  ├─ idle threshold & allow roaming → JumpDown → DesktopRoam
  └─ work event → MenuBarWorking

DesktopRoam
  ├─ InspectIcon → Kick / PretendEat / Sit
  ├─ MouseNearby → Chase / Avoid / LookAt
  ├─ UserActive → ReturnHome
  ├─ Alert → ReturnHome → AlertOverlay
  └─ Timeout → ReturnHome → MenuBarIdle
```

### 7.2 行为触发示例

| 触发条件 | 表现 | 是否需要 API |
|---|---|---|
| Codex 正在长任务 | 看书、敲键盘、低频挠头 | 否 |
| DSH 请求批准 | 举牌、探头、提醒 | 否 |
| Codex 任务结束 | 庆祝、比心、短气泡 | 否 |
| CPU 长时间偏高 | 冒汗或摇晃 | 否 |
| 3 分钟空闲 | 偶尔探头 | 否 |
| 10 分钟空闲 | 小概率下桌面游荡 | 否 |
| 鼠标靠近角色 | 看向鼠标、缩头、躲开 | 否 |
| 角色遇到桌面文件 | 踢/咬/假装吃、根据文件名本地吐槽 | 否或偶尔 |
| 特殊任务完成 | 一句新生成的抽象台词 | 可选低频 API |

默认时间、触发概率和动作冷却都可在设置里调整。真正的“闲置”应综合系统输入空闲时间、前台全屏/会议状态、电源与是否允许动画来判断。

### 7.3 台词系统

采用三层：

1. **本地台词库（免费）**：几百句按 `agent / system / browser / finder / idle / error / mouse` 分类。
2. **事件模板（免费）**：`{agent} 又在摸鱼？`、`{project} 总算跑完了。` 等模板，不传输隐私内容。
3. **低频 DeepSeek（付费）**：只传必要的匿名上下文，生成最多几十字的句子；缓存、去重、审查、限额。

举例：“代码很有想法，可惜电脑不太认同。”“你这文件夹像垃圾填埋场。”“Codex 终于肯回你了。”

## 8. 用户界面：点击鲸鱼娘后的 Dashboard

**默认面板**尽量做成小巧的下拉窗口，而不是完整桌面软件控制台。

### 面板布局

- **顶部**：鲸鱼娘半身、当前情绪、简短台词。
- **系统指标**：CPU 占用、内存占用、网络上下行、磁盘空间、电池与充电状态；打开活动监视器。
- **Agent 区**：Codex / DSH 活跃会话数量、当前任务、等待输入、完成/异常、额度（若可读），点击跳转。
- **通知区**：最近若干条高优先级事件、清除已读。
- **邮箱**：未读计数、重要邮件、打开邮箱。
- **快速设置**：游荡开关、静音/专注模式、动画频率、API 使用量、首选 Agent。

### 快捷交互约定

- 单击：打开面板（或切换互动模式，须在设置里固定默认行为）。
- 鼠标悬停一段时间：探头；移动离开后缩回。
- 右键：应用菜单。
- 长按/角色附近戳动：大姿态互动。
- 菜单栏的重要通知小角标：仅表示待办，不覆盖角色动作主体。

## 9. 性能、Token、权限与安全

### 9.1 目标而非实测值

| 项目 | 工程目标 / 策略 |
|---|---|
| 空闲 CPU | 尽量低于 0.5%（长期平均） |
| 动画 CPU | 尽量低于 1%（常规低帧率状态，不含短时峰值） |
| 常驻内存 | 优先控制在约 100 MB 以内 |
| 菜单栏动画 | 约 4–8 FPS 或静止时停更 |
| 系统资源采样 | 默认每 2–5 秒一次，隐藏面板时降低频率 |
| 空闲检测 | 使用系统输入空闲时长，不扫描键盘内容 |
| AI 新台词 | 通常每天不超过 10–20 次请求，按预算动态调整 |
| API 成本 | ¥0.50/天软限额，¥2/天硬限额 |
| 云端不可用 | 自动使用本地台词，不阻塞 UI |

上述数据须在 M4 设备上用 Activity Monitor、Instruments 做真实测量。不要把它们当作现有开源项目已经达到的指标。

### 9.2 API 成本控制

- 使用便宜的短文本模型/非思考模式；配置中单独维护实际模型单价。
- 严格限制输入/输出 Token，上游只提供简短事件摘要。
- 同一情境冷却与缓存；重复事件不调用模型。
- 预算按实际 usage + 请求前估计的最大输出花费管理。
- 达到硬上限时当天不再发送桌宠自身的新增模型请求。
- 模型费用只计算桌宠，不包含现有 DSH/Codex 会话。

### 9.3 权限分级

| 权限/数据 | 默认 | 何时申请 |
|---|---|---|
| 系统资源信息 | 最小读权限 | 运行常规系统面板时 |
| 通知权限 | 需用户同意 | 第一次开启系统通知时 |
| 邮箱登录/OAuth/IMAP | 不连接 | 开启邮件提醒时 |
| 辅助功能 Accessibility | 不默认授权 | 启用可见图标定位/更深入窗口交互时 |
| 屏幕录制 | 不默认授权，也不作为首选实现 | 只有未来明确新增视觉识别功能时 |
| 文件访问 | 最小范围，默认不改写 | 用户明确启用某项功能时 |
| 本地网络 | 不开放服务 | 启用 Windows/ComfyUI 远程事件时 |

隐私底线：不记录键盘输入；不读取邮件全文作为默认行为；不持续截图；不自动给危险命令放行。后台事件接口限制到本机 loopback 或受认证的配对设备。

## 10. 开发阶段和验收标准

### Phase 0：技术审计与最小 PoC

**任务**：确认以上仓库是否真实可构建、API 范围和授权；检查 AgentPet 是否易于剥离多余功能；验证 Mac M4 上 `NSStatusItem + NSPanel` 锚点动画。

**交付**：可启动的原生项目；菜单栏占位动画；单个透明角色窗口；DSH/Codex 模拟事件注入；开源依赖与素材许可清单。

**验收**：软件启动/退出正常，透明窗不抢键盘焦点，模拟事件可在菜单栏显示，不依赖外部模型 API。

### Phase 1：日常可用 MVP

**任务**：菜单栏微型鲸鱼娘、基础动作、悬停探头、点击系统 Dashboard、RunRat 风格系统指标、Codex/DSH 真实消息接入、事件队列与重复通知处理、设置与日志。

**验收**：Codex/DSH 各至少一个真实任务可被可靠通知；双 Agent 并发无状态覆盖；等待批准比普通完成优先；退出后无残留悬浮窗；CPU 和内存达到可接受水平。

### Phase 2：半身互动与角色性格

**任务**：大角色形态、鼠标跟踪、戳脸/拖动/挥手、有限姿态切换、通知气泡、预置吐槽、专注与安静模式。

**验收**：正常文字输入与文件拖动不受影响；角色可收起；多显示器/刘海屏/全屏边界基本正确；网络断开仍可互动。

### Phase 3：桌面自主游荡

**任务**：系统空闲检测、从菜单栏跳落/返回、桌面自由行走、鼠标与 Dock 动画、Finder 图标可见性实验、视觉踢打与假吃图标、小剧场。

**验收**：无真实文件改动；用户活动恢复后自动收敛；图标坐标不可获取时优雅降级；长时间后台运行不显著增加能耗。

### Phase 4：智能增强与可选外部接入

**任务**：邮箱优先级、低频 AI 台词、额度阈值提醒、每日任务摘要、Windows/ComfyUI 结构化事件接收、语音/成长系统。

**验收**：预算硬上限生效；所有外部事件能够去重与跳转；邮箱敏感内容不默认上传；远程事件必须认证。

### 共同质量门槛

- 功能测试：Agent 同时工作、工具报错、Hook 重复、会话异常退出、断网、睡眠唤醒。
- UI 测试：菜单栏自动隐藏、Dock 四周位置、多屏/Retina、Mission Control、Spaces、全屏窗口。
- 安全测试：点击穿透、不会误操作桌面文件、系统权限可以单独撤销。
- 能耗测试：空闲 1 小时、持续编程 1 小时、开启游荡与关闭游荡的 CPU/能耗/内存对比。
- 可维护性：事件协议版本化，第三方接口故障不使主程序崩溃。

## 12. 关键风险、验证任务与待定事项

| 风险/待定事项 | 影响 | 推荐处理 |
|---|---|---|
| AgentPet 实际是否覆盖所有 Codex 客户端 | 通知漏报 | 分别对 CLI、桌面 App、IDE 版做实测；缺失的做独立适配器 |
| DSH Profile 与 Cordis 事件结构变化 | 状态失效 | 在插件中版本化适配，模拟事件做回归测试 |
| whale-girl 角色美术的再分发权限 | 项目无法公开发布素材 | 先审查来源与许可，必要时自绘或申请授权 |
| 菜单栏固定左侧 | 违背 macOS 正常菜单栏 API 约束 | 默认右侧状态区；若坚持左侧，单独做模拟浮层，不纳入 MVP |
| Finder / Dock 图标坐标不可用 | 踢图标效果不精准 | 第一版视觉假互动，位置获取作为渐进增强 |
| 透明窗口拦截鼠标 | 干扰日常工作 | 角色命中区外透传，做全屏/多屏与拖拽回归测试 |
| 邮箱接入方式差异 | 部分邮箱无法实时通知 | 先 Apple Mail / 选定 IMAP 服务；按供应商增加独立适配器 |
| 误判长推理为“假死” | 错误警报 | 区分活动时间与进程存活，只显示“疑似停滞” |
| API 预算超支 | 长期成本不符 | 规则引擎优先、短输出、缓存、严格每日上限 |
| 代码许可与依赖冲突 | 无法直接合并项目 | Phase 0 审计后再决定 Fork / 移植 / 重写 |

### 最重要的实施决策

1. **优先保持 AppKit/Swift 原生技术栈**，不要为了少量动画引入 Electron 常驻 Runtime。
2. **先确保 Agent 通知可靠，再做复杂游荡动作**：它是工具价值的核心。
3. **所有对 Finder 文件的动作默认只演戏**：即使桌宠看起来“吃掉了文件”，真实文件也完全不受影响。
4. **把桌宠状态机、Agent 事件、AI 台词彼此解耦**：模型不可用时桌宠仍能完整运作。
5. **先审查上游和图像授权**：不要在没有许可验证的情况下将原素材一并公开打包。

## 13. 给 Codex / DSH 的开工指令（可直接复制）

> 请依据本文档启动 WhaleGirl for macOS 项目的 Phase 0。先审计文中列出的 AgentPet、RunRat、DSH Pet、whale-girl、Aibo 和 QiuQiu 等开源项目（源码、许可证、依赖、适配 macOS 版本、可重用模块），不要假定所有 README 功能都已稳定实现。以原生 Swift/AppKit/SwiftUI 为主，在 Mac Apple Silicon 上做一个可运行 PoC：菜单栏显示占位鲸鱼头像、鼠标悬停后有透明半身窗探出、点击打开一个只读系统指标面板、能够接收两种来源的模拟 Agent 事件并正确维护多会话状态。明确写出实际复用的源文件、许可证合规情况、未解决的问题及下一步任务。不要自动修改 Finder 文件，不要让窗口遮挡正常鼠标操作，不要引入持续 AI API 调用。

## 14. 一句话结论

> **WhaleGirl = AgentPet 原生 Agent 通知主干 + RunRat 菜单栏/系统监控 + DSH Pet 事件桥接 + whale-girl 鲸鱼娘图集 + 自研 MenuBar↔Overlay 动画与 Desktop Roaming + 本地行为/台词引擎。**
>
> 平时安静待在菜单栏，有事时探头提醒，互动时跳出来，没人操作时才下桌面和图标、鼠标“捣乱”；长期运行低功耗、不破坏文件、额外模型成本每天不超过 ¥2。
