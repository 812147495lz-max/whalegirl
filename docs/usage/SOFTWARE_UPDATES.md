# GitHub 软件更新

菜单栏图标中键／Option+右键 → **检查软件更新…**。窗口可查看当前版本、检查结果、下载进度和错误，也可以打开 GitHub 发布页。菜单和窗口都可切换 **自动更新鲸鱼娘**。

自动更新默认开启：启动约20秒后按检查间隔执行，每6小时检查一次固定仓库 `812147495lz-max/whalegirl` 的最新正式 Release。默认发现更高版本就下载、校验、原位安装并重启。关闭自动更新后可手动检查；发现新版后点击“更新并重启”。下载过程中可取消；关闭更新窗口不会中断后台任务。有保存对话框时先等待对话框关闭。后台检查失败保持安静，不用桌宠探头反复播报。

只比较正式版本号，不因主分支增加提交而下载源码编译，不接受草稿、预发布或降级。仅安装比当前应用更高的正式版本，不会降级。

## 发布包要求

- 版本标签用 `v1.8`、`v1.8.1` 等纯数字版本。自动安装附件名为 `WhaleGirl-v1.8-Universal.zip`（随对应标签变化），不是 GitHub 自动生成的源码 ZIP。
- 附件必须处于 uploaded 状态，GitHub Release API 要提供有效的 `sha256:…` digest；发布包地址限本仓库的 releases/download 路径。不需要将登录凭据放入应用。
- ZIP 内主应用为 `WhaleGirl.app`，Bundle ID 保持 `io.whalegirl.app`，执行文件名保持 `WhaleGirl`，版本与发布标签一致，包含 arm64 和 x86_64，最低系统版本不高于当前系统。
- 新版保留 `WhaleGirlUpdaterProtocolVersion=1` 以及安装辅助入口与启动确认逻辑。这样安装后可确认新版本真正进入应用启动流程。
- ZIP 不得包含符号链接、越界路径、加密项、ZIP64 或不相关顶层文件；当前原生发行包符合该格式。压缩文件上限1.5GB，累计解压上限4GB。新格式不兼容时走手动下载。

## 安装与数据

应用目录必须可写，且不能在只读DMG或AppTranslocation目录中运行。下载/校验/解压放在应用旁独立的私有临时目录，留足空间后才开始。SHA-256与GitHub API值一致后再检查ZIP路径、应用身份、系统/架构、更新协议及严格深层签名。

独立辅助进程等待原应用正常退出，保留原安装名称与位置，替换应用后启动新版；新版启动确认成功后删除事务目录和原应用临时副本。不会积累每个版本的整套安装包。下载/校验失败不退出原应用；替换/启动失败尽可能恢复当前可用版本，并暂停该版本后台自动重试，用户可手动重试。若恢复本身失败，保留事务目录供修复，不盲目删除唯一旧应用。

只替换 `.app`，保留原有UserDefaults、用户数据目录、CSV台词、余额观察与Token报表、集成配置。不会重装Hook或重启DSH/Codex。更新检查为匿名HTTPS；不上传游戏库、会话、提示词、账户用量或凭据。

## 信任与验证范围

更新源固定为本项目GitHub仓库。API提供的摘要用于验证包内容与同一次发布一致，严格签名验证用于检查包完整性；当前应用为ad-hoc签名，没有独立发布公钥或Apple公证声明，GitHub仓库及其HTTPS/API是此更新通道的信任来源。未改变Gatekeeper或系统证书设置。

版本/发布元数据与ZIP边界有针对性测试；真实v1.5 ZIP可通过结构验证。更高版本的线上完整下载安装，要等后续Release提供对应版本的正式包；不以本地夹具替代该项验收。本次没有自动发布新版本到GitHub。

## v1.7.1：本机认证与公开备用通道

实测本机GitHub API返回403且匿名配额为0。现在先使用Release API；只有网络/接口不可用时，备用读取GitHub官方 `releases/latest` 重定向，仍只接受本仓库纯数字正式版本地址。需要更新时，从同一标签下载 `SHA256SUMS-v版本.txt`，精确匹配对应ZIP的唯一SHA256，并用该附件的HTTPS HEAD响应确认大小，再进入相同的包校验/原位安装流程。无校验文件、重复/错名摘要或过大包均停止，不使用第三方镜像或保存登录Token。

API限流与备用发布页均不可用时，明确提示限流并按服务器重置时间安排重试（至少间隔5分钟）；其他检查失败约1小时后自动重试，成功后恢复6小时检查。手动检查可立即重试。当前本机发布页HTTPS连接也曾超时，因此本轮不能声称已通过更高线上版本的完整下载验收；接口恢复或网络可达时使用同一通道。

## 复用本机已有的 GitHub 认证

优先自动寻找已安装的 GitHub CLI（Homebrew标准路径及 `/usr/bin/gh`），通过 `gh api --hostname github.com` 查询固定仓库的正式Release。认证成功的通道也通过 `gh release download --repo github.com/812147495lz-max/whalegirl` 下载精确匹配的ZIP，然后执行同样的SHA256/包结构/签名检查。不会调用 `gh auth token`，不会复制、显示或另存Token，登录和钥匙串继续由现有CLI管理，不发起新的登录或权限申请。

CLI子进程为非交互模式，禁用更新通知/调试输出，明确固定github.com；有输出大小、下载大小、时间上限和取消回收。查询失败时再尝试匿名API/官方发布页，错误提示会区分“本机CLI查询未成功”与公开通道问题。本机已检测到启用的GitHub登录，但本轮`gh auth status`报告timeout，直接API调用也出现TLS握手超时；这表示连接本身尚未完成，不能将它误写成没有登录或认证已成功返回Release。网络恢复后重试，无需在鲸鱼娘填写密钥。
