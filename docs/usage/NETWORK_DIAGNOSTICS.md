# 网络诊断与测速（v1.1）

入口：电脑信息面板“网络”旁的“测速”按钮。点击后会在信息卡旁弹出快捷选项，不会立即发送测试请求。

## 快捷检测和鲸鱼娘播报

1. 在快捷面板的“目标”中选择 Google、GitHub、百度、哔哩哔哩或自定义网址/IP。
2. 选择综合检测、延迟与路由、下载测速或独立公网带宽，点击“开始检测”。
3. 综合检测依次执行，不与其他测试争用带宽。完成后，鲸鱼娘用气泡显示已取得的平均延迟、确认到达的跳数和实际下载速度；未响应或未到终点会明确说明，不补造数值。小页面结果另有参考提示。主动停止不播报“测好啦”。
4. 点击“详情与设置”进入完整页面，查看逐跳IP、三次RTT、下载量/耗时以及独立公网带宽结果，可分别重测，并调整最大跳数（15/30/45/64）、目标下载流量上限（4/16/32MiB）、时间上限（5/10/20秒）和IPv4/IPv6。选项与结果由快捷面板和详情页共享，保留在当前运行会话内。

收起快捷面板或打开详情不会取消已启动的快捷检测。信息卡仍展开时由绳索上的鲸鱼娘播报，收回信息卡后则由菜单栏探头气泡播报；继续遵守全屏避让。快捷面板也保留本次摘要供查看。控制菜单中的“网络诊断与测速…”仍可直接打开详情。

## 目标和路由

可选择 Google、GitHub、百度、哔哩哔哩，或输入自己的域名、HTTP/HTTPS网址、IPv4/IPv6地址。网址带路径时，路由只追踪主机；目标下载使用完整网址（不含片段）。不接受账号密码、非HTTP协议、控制字符或命令行参数。路由协议可选IPv4/IPv6。

点击“路由追踪”后显示每跳的响应IP与三次往返延迟，默认最多30跳，详情可选15–64跳；后台超时为三倍最大跳数加10秒。三次探测可能经过不同IP，均保留在同一跳；工具返回的不可达标记（如!H）会显示。只有观察到目标IP正常回复才显示总跳数“已到达”，未到达不把已探测跳数当作完整路径长度。

RTT是本机到该跳的往返时间，不是相邻路由器之间的延迟。`*`表示未收到探测响应，可能是限速、过滤或不回复；不等于链路断开。CDN可能为同一域名选择不同终点，代理/VPN可能让系统路由与网页实际连接不同。

## 测速

- **目标下载测速**：对所选网址进行普通GET，流式计数后丢弃数据，不保存文件、Cookie或凭据。默认约16MiB或10秒后停止（详情可调整）；显示实际接收量、耗时和平均Mbps（含连接建立时间）。小于1MiB的响应仅作为页面传输参考，不代表带宽上限。IP目标若不支持对应HTTPS证书，需要使用实际可访问的网站/文件链接；不会跳过证书校验。
- **公网带宽测速**：使用macOS自带networkQuality，调用Apple测试服务，最多20秒测量/25秒进程超时；显示有效的下载、上传Mbps和可取得的空闲往返延迟。上下行同时测试，此项与上方所选网站无关，会产生测试流量。缺失项显示不可用；即使命令退出0，错误JSON或无有效吞吐量也不报成功。

同一时间只运行一种测试，避免彼此争用带宽。点击“停止”或退出应用会取消当前测试；关闭详情窗口会停止单项测试，快捷组合检测会继续至结束或手动停止。没有定时测速、持久化路由/网址历史、额外应用账号或系统权限修改。

## 实现与参考

平均延迟来自系统ping/ping6的三次ICMP探测，最多等待6秒；目标可能屏蔽ICMP，未取得时明确显示。系统traceroute/traceroute6使用参数数组直接启动，无Shell、无反向DNS查询；进程输出与运行时间有上限。现有网络速率采样仍表示当前实际流量，与主动测速分开。

macOS本机手册：`man traceroute`、`man traceroute6`、`man networkQuality`。networkQuality的dl_throughput/ul_throughput单位为bits/s，展示时除以1,000,000转为Mbps。官方服务参考：https://github.com/network-quality/server 。

界面整理：快捷面板只保留目标、项目、开始/停止与结果；详细页将参数收在“测试设置”中。完整测试解释可点问号查看。
